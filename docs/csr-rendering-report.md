# CSR 렌더링 점검 보고서

- 대상: VAN 뉴스 프론트엔드 (React + Vite SPA)
- 점검일: 2026-08-19
- 관련 티켓: [FE-2] 메타 태그 세팅 및 CSR 렌더링 점검

## 1. 점검 방법

로컬 개발 서버(`localhost:5173`)에서 브라우저 "페이지 소스 보기"(Ctrl+U)로
서버가 최초 응답한 원본 HTML을 확인했다. 이는 자바스크립트를 실행하지 않는
크롤러가 보는 문서와 동일하다.

## 2. 결과

### 정상 노출되는 항목
- `<title>`, `<meta name="description">`
- `<link rel="canonical">`, `<meta name="robots">`
- Open Graph / Twitter Card 메타 태그
- JSON-LD 구조화 데이터 (NewsMediaOrganization)

→ `index.html`에 정적으로 작성된 항목이므로 크롤러가 그대로 읽을 수 있다.

### 노출되지 않는 항목
- 페이지 본문 전체 (h1, 기사 제목, 기사 요약, 내부 링크 등)

원본 HTML의 body는 다음이 전부다.

    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>

→ 본문은 자바스크립트 실행 후 클라이언트에서 생성되므로,
   JS를 실행하지 않는 크롤러에게는 빈 페이지로 인식된다.

## 3. 영향 분석

| 크롤러 | JS 실행 | 본문 인식 |
| --- | --- | --- |
| Googlebot | 지원 (2차 렌더링 큐) | 지연·누락 가능 |
| 네이버 Yeti | 사실상 미지원 | 불가 |
| GPTBot / ClaudeBot 등 AI 크롤러 | 대부분 미지원 | 불가 |

본 프로젝트의 목표는 네이버·구글 검색 노출과 생성형 AI 인용 확보다.
현재 구조에서는 목표 중 네이버 검색과 AI 인용이 구조적으로 달성 불가능하다.

## 4. 해결 방안 비교

| 방안 | 작업량 | 효과 | 비고 |
| --- | --- | --- | --- |
| 프리렌더링 (vite-plugin-prerender 등) | 1일 | 정적 페이지 해결 | 동적 기사 페이지는 미해결 |
| SSR 도입 (Next.js 전환) | 2~3일 | 전체 해결 | 프로젝트 구조 재설계 필요 |
| 동적 렌더링 (크롤러에만 정적 HTML 제공) | 1~2일 | 전체 해결 | 별도 서버 필요, 구글 비권장 |

## 5. 결론 및 제안

메타 태그·구조화 데이터 세팅은 완료했으나, 본문 미노출 문제는
프론트엔드 렌더링 방식 자체의 문제이므로 본 티켓 범위를 넘어선다.

기사가 DB에서 동적으로 제공되는 구조를 전제하면 SSR 도입이 근본 해결책이다.
별도 티켓으로 분리하여 팀 논의 후 결정할 것을 제안한다.

## 6. 리스크·미결 사항

- 실제 도메인 미확정: canonical/og:url에 임시값(`van.example.com`) 사용 중.
  도메인 확정 후 일괄 수정 필요.
- og:image 미설정: 대표 이미지 확정 후 추가 필요.
